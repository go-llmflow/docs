Overview

go-llmflow documentation

go-llmflow is high-performance LLM inference and serving in Go. It is written for the case where one GPU cluster has several owners: each owner must get the share it paid for, and a share that its owner leaves idle must not be wasted.

Everything is pure Go (CGO_ENABLED=0) and BSD-3-Clause.

What is here

PageWhat it says
Gatewaythe gateway project (v0.6.0): an OpenAI-compatible gateway in front of vLLM. Its configuration, hierarchy and roles, admin API, how fair-share with borrowing works, prefix-cache isolation, overhead measurement, limitations and roadmap
Identityhow the gateway takes people from your identity provider: OpenID Connect tokens, administrator single sign-on, SAML federations through a bridge, SCIM provisioning, key rotation
Audit and loggingthe hash-chained admin audit log, its anchors and what they do not protect against, per-team request logs, retention, request policies
PII recognisersthe pii library (v0.1.0): e-mail, phone, IBAN, French NIR, payment cards and IP addresses found in text, checksum-validated, with the false positives measured
Fair-share on a co-owned GPU clustera guide: how two institutions can share a cluster of GPU servers with Slurm (batch), vLLM (inference) and a gateway (keys, quotas, priorities), reached from VS Code

Status

The organisation has two repositories with code. gateway has its current release at v0.6.0: virtual keys, budgets on every scope of an organisation, team, project and key hierarchy with delegated roles, HCL2 configuration, an admin API, fair-share with borrowing, per-tenant prefix-cache isolation, identity (OpenID Connect, single sign-on, SCIM), an anchored audit log, and guardrails (hide_secrets, pii, Llama Guard, Prompt Guard; the HTTP adapter is off by default). pii is a library, at v0.1.0, that recognises personal data in text; the gateway’s PII guardrail uses it. The Gateway page lists what it does, how it is configured, what was measured, and its open limitations and roadmap.

The guide is different in kind: it is a design and operations document for a cluster, written from the vendors’ documentation and from measurements, and it stands on its own. The gateway is the part of it that is being written in Go.
